# 75. Sort Colors

- 링크: https://leetcode.com/problems/sort-colors/
- 유형: 개수 세기 (카운팅 정렬). 투 포인터로도 풀 수 있다
- 날짜: 2026-10-27
- 상태: 혼자 풂, 통과. 단 `HashMap` 순서에 기대고 있어서 개수 배열로 재풀이 필요

## 접근

값이 0, 1, 2 세 가지뿐이라 정렬할 필요 없이 **개수만 세면** 된다.
`HashMap`으로 색깔별 개수를 센 뒤, 0 → 1 → 2 순서로 그 개수만큼 `nums`를 앞에서부터 덮어썼다.

## 시간복잡도 / 공간복잡도

- 시간: O(n)  (세기 1번 + 덮어쓰기 1번)
- 공간: O(1)  (키가 최대 3개)

## 다른 풀이

- **개수 배열**: 키가 0, 1, 2뿐이니 맵 대신 `int[] count = new int[3]`을 쓴다. `count[num]++`로 세고, `for (int color = 0; color < 3; color++)`로 덮어쓰면 순서가 항상 보장되고 색깔별 `if`도 필요 없다.
- **Dutch National Flag (한 번 순회)**: 포인터 `low`, `mid`, `high`를 두고 `mid`가 0이면 `low`와, 2면 `high`와 바꾼다. 0은 앞으로, 2는 뒤로 모인다. 시간 O(n), 공간 O(1). 문제의 follow-up(한 번 순회 + 상수 공간)이 이 방법을 묻는다.

## 막혔던 점

- 통과했지만 "keySet()은 0, 1, 2 순서를 보장하지 않는다"는 경고가 떴다.
  - `HashMap`은 순서를 보장하지 않는다. 그런데 `Integer`의 해시값은 자기 값 그대로라 0, 1, 2가 0, 1, 2번 버킷에 들어가고, `keySet()`이 버킷을 0번부터 훑어서 **우연히** 오름차순으로 나왔다.
  - 이건 자바 명세가 아니라 구현 세부사항이다. 키가 문자열이거나 큰 수면 순서가 달라진다.
- **순서가 필요하면 `HashMap`을 쓰지 않는다**: 키 정렬은 `TreeMap`, 넣은 순서는 `LinkedHashMap`, 키가 작은 정수 범위면 그냥 배열.
