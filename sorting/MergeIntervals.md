# 56. Merge Intervals

- 링크: https://leetcode.com/problems/merge-intervals/
- 유형: sorting (시작점 기준 정렬 후 한 번 훑으며 합치기)
- 날짜: 2026-10-23
- 상태: 어떤 자료구조를 쓸지 감이 안 와서 힌트를 받고, 여러 번 고쳐서 직접 작성, 통과

## 접근

시작점 기준으로 정렬하면 겹칠 수 있는 구간이 항상 바로 옆에 온다.
`answer[0]`에 첫 구간을 넣고, 다음 구간부터 **결과의 마지막 구간(`answer[pos-1]`)**과 비교한다.
- 겹치면(`마지막 끝점 >= 이번 시작점`) 마지막 구간의 끝점을 `Math.max`로 늘린다. `pos`는 그대로다.
- 안 겹치면 `answer[pos]`에 새로 넣고 `pos++` 한다.

마지막에 `Arrays.copyOf(answer, pos)`로 실제로 쓴 칸만 잘라서 반환한다.

## 시간복잡도 / 공간복잡도

- 시간: O(n log n)  (정렬. 합치는 건 O(n))
- 공간: O(n)  (결과 배열)

## 막혔던 점

- 스택, 큐, 해시 같은 특별한 자료구조가 필요 없다. **"구간이 겹친다/합친다" → 먼저 시작점 기준 정렬.**
- 정렬 람다에서 `a`, `b`는 인덱스가 아니라 원소(`int[]`)다. `intervals[a][0]` ❌, `[a][0]` ❌ → `a[0]` ✅.
- 처음에는 `intervals[i]`와 `intervals[i+1]`(원래 배열의 이웃)을 비교했다.
  - `[[1,10], [2,3], [4,5]]` → `[4,5]`는 `[2,3]`과는 안 겹치지만, 이미 합쳐진 `[1,10]`과는 겹친다.
  - 비교 대상은 **지금까지 합친 덩어리**(`answer[pos-1]`)다. Min Stack에서 `min.peek()`(누적 최솟값)과 비교한 것과 같은 생각이다.
- 합쳐도 `pos++`를 해서 빈칸 `[0,0]`과 비교했다 → `pos++`는 새로 넣을 때(`else`)만 한다.
- 끝점을 `intervals[i][1]`로 덮어써서 `[[1,10], [2,5]]` → `[1,5]`가 됐다 → `Math.max`로 더 먼 쪽을 고른다.
- 결과 개수를 미리 모를 때: 넉넉한 배열에 쌓고 `Arrays.copyOf(answer, pos)`로 자르기. 2차원 배열도 된다.
- 참고: 시작점 기준으로 정렬했으므로 `Math.min`으로 시작점을 갱신하는 줄은 없어도 결과가 같다.
