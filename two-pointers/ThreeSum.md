# 15. 3Sum

- 링크: https://leetcode.com/problems/3sum/
- 유형: 정렬 + 투 포인터 (하나를 고정하고 나머지 둘은 Two Sum II, [노트](https://github.com/DaeunSon/algorithm-notes/tree/main/05-two-pointers)의 모양 1)
- 날짜: 2026-10-31
- 상태: 처음 틀은 방향이 달라서 뼈대 힌트를 받고, 두 번 고쳐서 통과

## 접근

1. 정렬한다. 같은 값이 붙어 있게 되고, 투 포인터를 쓸 수 있게 된다.
2. `i`로 첫 수 `a`를 하나 고정한다. `a`가 앞과 같은 값이면 건너뛴다.
3. `a`의 오른쪽에서 `b + c = -a`인 두 수를 양 끝 투 포인터(Two Sum II)로 찾는다.
4. 답을 찾으면 `Arrays.asList(a, b, c)`로 **새 리스트**를 만들어 넣고, `left`가 같은 값이면 건너뛴다.

## 시간복잡도 / 공간복잡도

- 시간: O(n²)  (정렬 O(n log n) + 바깥 `for` n번 × 안쪽 투 포인터 n번. n이 최대 3000이라 충분)
- 공간: O(1)  (결과 리스트와 정렬 제외)

## 막혔던 점

- 처음에는 양 끝 투 포인터 하나로 두 수만 봤다. 세 수 문제는 **하나를 고정**하면 이미 푼 두 수 문제(Two Sum II)가 된다.
- 리스트 하나(`int_list`)를 만들어 계속 `list.add(int_list)` 했다. `add`는 복사가 아니라 **참조**를 넣어서, 모든 칸이 같은 리스트를 가리킨다 → 답마다 `Arrays.asList(...)`로 새로 만든다.
- 합이 작을 때 `right--`, 클 때 `left++`로 방향이 반대였다. 예제 1은 우연히 맞아서 놓치기 쉬웠다. `[-3, 0, 1, 2]` → `[]`(정답 `[[-3, 1, 2]]`)에서 드러났다.
- 답을 찾은 뒤 같은 값 건너뛰기를 빠뜨려서 `[-2, 0, 0, 2, 2]`에서 `[-2, 0, 2]`가 두 번 나왔다.
  - `left`나 `right` **한쪽만** 건너뛰어도 된다. `a`가 고정되면 `b + c`가 정해져 있어서, `c`가 같으면 `b`도 같고(중복), `c`가 다르면 `b`도 다르다.
  - 건너뛰는 `while`도 `left < right &&`를 맨 앞에 둔다.

## 재풀이 기록 (2026-11-08)

- 결과: 혼자서는 못 풂 → 단계별 힌트와 빈칸 뼈대를 보고 작성, 통과 (✗). 지난번과 같은 곳에서 다시 막힘
- 막힌 순서
  - 답 선언 `List<List<Integer>> ans = new ArrayList<>();`부터 헷갈림 (`>` 빠짐, 꺾쇠 안에 변수 이름 `list`를 씀)
  - 바로 옆 두 수(`nums[i] + nums[i+1]`)만 더함 → 세 수는 떨어져 있어도 된다
  - 정렬 + 삼중 `for` → 중복이 나오고 O(n³)라 n = 3000에서 시간 초과
  - 투 포인터 대신 `mid`를 쓴 이분 탐색으로 씀 + 바깥 `for i` 없음 + 답을 찾고 `left`, `right`를 안 움직임 → 같은 리스트를 끝없이 넣어 **Memory Limit Exceeded**
  - 답을 찾은 뒤 같은 값 건너뛰기 빠뜨림 → `[-2, 0, 0, 2, 2]`에서 중복
  - 건너뛰기 조건을 `!=`로 반대로 씀 → 새 값을 다 건너뛰어서 `[-1, 0, 1]`을 놓침
- 이해한 것
  - `left++` 뒤에는 방금 쓴 칸이 `left - 1`이 된다
  - `i` 건너뛰기는 "첫 번째 수가 같은 값으로 다시 고정되는 것"을, `left`/`right` 건너뛰기는 "같은 `i` 안에서 다시 나오는 것"을 막는다. 서로 대신할 수 없다
  - `left`만 다른 값으로 옮겨도 `nums[left] + nums[right]`가 고정이라 같은 `right` 값으로는 다시 답이 안 된다
- 다음에 떠올릴 한 문장: "**정렬 → `i` 고정 → 나머지는 Two Sum II(양 끝 투 포인터, `mid` 없음).** 같은 값은 `i`와 `left`에서 건너뛴다."
