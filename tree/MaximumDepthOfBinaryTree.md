# 104. Maximum Depth of Binary Tree

- 링크: https://leetcode.com/problems/maximum-depth-of-binary-tree/
- 유형: tree / DFS (재귀)
- 날짜: 2026-11-11
- 상태: 트리 첫 문제. 개념 설명 + 빈칸 뼈대(합치기 줄 한 번 틀림) 후 Google Docs에 처음부터 써서 통과

## 접근

루트의 왼쪽 아래도 트리, 오른쪽 아래도 트리다. 각각의 깊이를 재귀로 **믿고 맡긴 뒤**, 더 깊은 쪽에 나 자신(1)을 더한다.
종료 조건은 `root == null`이면 0.

## 시간복잡도 / 공간복잡도

- 시간: O(n) (노드마다 한 번 방문)
- 공간: O(h) (재귀 호출 스택, h는 트리 높이. 한쪽으로만 뻗은 트리면 O(n))

## 막혔던 점

- 합치기를 `left + right + 1`로 씀 → 예시 트리에서 3이 아니라 5가 나옴. 그건 **노드 개수**다. 깊이는 한 갈래 길이라 두 쪽을 더하지 않고 **한쪽만 고른다** → `Math.max(left, right) + 1`
- 트리 재귀의 모양: 종료 조건 / 왼쪽 맡기기 / 오른쪽 맡기기 / **합치기**. 문제마다 보통 합치기 줄만 바뀐다
  - 최대 깊이: `Math.max(left, right) + 1`
  - 노드 개수: `left + right + 1`
- LeetCode 배열 표기 `[3,9,20,null,null,15,7]`은 위에서부터 한 줄씩, 왼쪽에서 오른쪽으로 읽은 것
