# 733. Flood Fill

- 링크: https://leetcode.com/problems/flood-fill/
- 유형: 격자 탐색, DFS (재귀)
- 날짜: 2026-11-12
- 상태: 격자 탐색 첫 문제. 페인트 통 비유 + 단계별 그림 + 빈칸 뼈대(①~⑦ 정답)를 본 뒤 LeetCode에서 직접 작성. 1차에서 "새 색 = 원래 색" 처리를 빠뜨림 → 예시 2 힌트 보고 추가해서 통과

## 접근

시작 칸과 같은 색으로 **상하좌우로 이어진 칸**을 전부 새 색으로 바꾼다. 104번 재귀 틀과 같은 모양:
멈춤(격자 밖 / 원래 색 아님) → 칠하기 → 위·아래·왼쪽·오른쪽에게 맡기기.
칠한 칸은 색이 바뀌어서 다시 와도 멈춤 → **칠하기 자체가 방문 표시**라 방문 배열이 필요 없다.
이어진 칸을 전부 바꾸면 되고 순서는 상관없어서 DFS든 BFS든 정답. 코드가 짧은 DFS 재귀를 고름.

## 시간복잡도 / 공간복잡도

- 시간: O(m × n) (칸마다 최대 한 번 칠함)
- 공간: O(m × n) (재귀 호출 스택, 최악에는 모든 칸이 이어진 경우)

## 막혔던 점

- 1차: `if (image[sr][sc] == color) return image;`를 빠뜨림 → 새 색이 원래 색과 같으면 칠해도 색이 안 바뀌어 **방문 표시가 안 남음** → 두 칸을 끝없이 오가다 StackOverflowError (예시 2)
- DFS/BFS 이름을 통째로 반대로 알고 있었음 → **D**FS = **D**eep(끝까지 갔다 돌아옴, 재귀/스택), **B**FS = **B**road(층별, 큐). 큐는 개념, `LinkedList`/`ArrayDeque`는 큐를 만드는 재료
- 꼭 골라야 할 때: 최단 거리·최소 횟수·층별 → BFS / 이어진 곳 전부 → 둘 다 / 모든 경로 시도 → DFS
- 멈춤 조건 하나가 "칠할 대상 고르기"와 "이미 왔는지" 두 가지를 같이 한다. "color가 아닌 칸 전부 칠하기"로 바꾸면 `== color`면 멈춤 (이때는 같은 색 예외 처리가 필요 없음)
- 칠하기를 4방향 호출 **전에** 하는 이유: 먼저 표시해야 이웃이 돌아왔을 때 멈춤. 호출 뒤에 칠하면 이웃이 아직 원래 색인 이 칸으로 다시 와서 무한 재귀
