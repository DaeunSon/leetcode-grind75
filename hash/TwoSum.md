# Two Sum

- 링크: https://leetcode.com/problems/two-sum/
- 유형: hash
- 날짜: 2026-10-06
- 상태: 이중 for문으로 먼저 직접 풂 → 해시맵 방식은 풀이 안내를 받은 뒤 작성 (재풀이 필요)

## 접근

값 → 인덱스를 저장하는 HashMap을 만들고 배열을 한 번 순회한다.
각 원소 `nums[i]`에서 필요한 짝 `target - nums[i]`가 맵에 이미 있는지 확인하고,
있으면 `{짝의 인덱스, i}`를 반환한다. 없으면 현재 원소를 맵에 저장한다.

## 시간복잡도 / 공간복잡도

- 시간: O(n)  (이중 for문은 O(n²))
- 공간: O(n)  (맵에 최대 n개 저장)

## 막혔던 점

- 처음에는 이중 for문으로 풀었고, 해시맵으로 시간복잡도를 줄이려 했다.
- 확인(`containsKey`)을 먼저 하고 그다음에 기록(`put`)해야 같은 원소를 두 번 쓰지 않는다.

## 재풀이 기록

- 2026-11-06 (20분, 이중 for문으로 통과 → 해시 풀이는 아직 못 떠올림, 재풀이 필요)
  - 처음엔 정렬 + 이분 탐색을 하려다가 **정렬하면 원래 인덱스를 잃는다**는 걸 알아챔
  - 습관적으로 `mid`를 쓰다가, 양 끝에서 좁히는 건 이분 탐색이 아니라 투 포인터(`left++`, `right--`)라는 걸 알게 됨
  - 해시맵에 `nums[i] → i`를 넣는 것까지는 했지만, 꺼내는 방법(`containsKey`, `get`)과 target과 비교하는 방법(`target - nums[i]`를 키로 찾기)을 몰랐음
  - 다음에 쓸 규칙: 이중 for문의 **안쪽 for문이 "짝이 있나?"를 찾는 일**이면, 그 찾기를 해시로 바꾼다
  - 같은 날 설명을 듣고 해시 버전(찾기 → 넣기)도 직접 작성해서 통과. `containsKey`, `get`이 바로 떠오르지 않았음

## 재풀이 기록 (2026-11-08, 2차)

- 결과: ○ (힌트 없이 해시로 통과). 금요일엔 이중 for로만 통과했는데 이번엔 처음부터 해시.
- 처음엔 `for`로 맵에 전부 먼저 넣고, 다음 `for`에서 `containsKey(need)`를 확인 → 틀림.
  - 맵에 **나 자신도 이미 들어 있어서**, `need`가 내 값과 같으면 나와 나를 짝지어 버림. 예: `[3,2,4]`, target 6 → `i = 0`에서 `need = 3`을 찾고 `[0,0]`.
  - 같은 값이 여러 개면 키가 하나라 **마지막 인덱스로 덮어써짐** (`[3,3]` → `{3: 1}`).
  - 넣기 전에 찾으면 맵에는 **나보다 앞쪽 원소만** 있으니 자기 자신과 짝지을 일이 없다. 같은 값 두 개도 두 번째 3이 앞의 3을 찾음.

## 재풀이 기록 (2026-11-13, 면접 당일 워밍업, Google Docs 백지)

- 결과: △ → ○ (한 번 지적받고 고쳐서 정답)
- 잘한 것: 코드 전에 "이중 for문이면 10^8 → HashMap"이라고 근거를 적음, key = 값 / value = 인덱스를 정확히 정함, 중괄호 짝 맞음
- 틀린 곳
  - 1차: `map.put`을 아예 안 씀 → map이 계속 비어서 항상 `[0, 0]` 반환. **"찾기 → 넣기"에서 넣기 줄이 빠짐**
  - 첫 줄 주석을 `/`로 시작 → 컴파일 에러 (`//`)
  - 백지에서 `import java.util.*;` 생략 (LeetCode는 자동)
  - 엣지 케이스로 "빈 배열"을 말함 → 제약이 `nums.length >= 2`라 들어오지 않음. 말할 엣지 케이스는 **같은 값 두 개 `[3,3]`**(그래서 찾고 나서 넣는다)와 음수
- 다음에 떠올릴 한 문장: "**찾고, 없으면 넣는다.** 엣지 케이스는 제약을 보고 말한다."
