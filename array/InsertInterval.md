# 57. Insert Interval

- 링크: https://leetcode.com/problems/insert-interval/
- 유형: 구현 (이미 정렬된 구간을 세 무리로 나눠 한 번 훑기)
- 날짜: 2026-10-27
- 상태: 세 무리 뼈대를 힌트로 받고, 여러 번 고쳐서 직접 작성, 통과. **꼭 재풀이** (안 보고 다시 짜기)

## 접근

`intervals`는 이미 시작점 기준으로 정렬되어 있다. 새 구간을 기준으로 기존 구간은 **순서대로** 세 무리로 나뉜다.

```
intervals = [[1,2], [3,5], [6,7], [8,10], [12,16]],  new = [4,8]

[1,2]                       ① 완전히 왼쪽: 끝 < 새 시작        → 그대로 넣기
      [3,5] [6,7] [8,10]    ② 겹침: 시작 <= 새 끝              → 새 구간에 합치기 (min, max)
                    [12,16] ③ 나머지 (완전히 오른쪽)            → 그대로 넣기

결과: [[1,2], [3,10], [12,16]]
```

`pos` 하나를 세 `while`이 이어서 쓴다. ②가 끝난 뒤 합친 새 구간을 **딱 한 번** 넣는다. 결과 개수를 모르므로 `List<int[]>`에 담고 `toArray(new int[result.size()][])`로 바꾼다.

## 시간복잡도 / 공간복잡도

- 시간: O(n)
- 공간: O(n)  (결과 리스트)

## 막혔던 점

- 처음 생각: 새 구간을 넣고 정렬한 뒤 Merge Intervals로 합치기 → 통과는 하지만 O(n log n). **입력이 이미 정렬되어 있다는 조건**을 쓰면 O(n)에 된다.
- Merge Intervals 구조(결과의 마지막과 비교)를 그대로 가져와서 꼬였다. 이 문제는 비교 기준이 **새 구간 하나**라서 세 무리로 나누는 게 단순하다.
- `List<int[]>`는 1차원이 아니라 "`int[]`를 칸으로 가진 리스트"다. `result.add(intervals[i])`는 `[시작, 끝]`을 통째로 넣는다.
- `while`에서 `pos++`를 빠뜨려 무한 반복.
- ② 조건을 `newInterval[1] <= intervals[pos][0]`로 써서 반대(오른쪽에 있는 경우)를 확인했다 → 겹침은 `intervals[pos][0] <= newInterval[1]`.
- **범위 확인**: 값 조건이 끝까지 참일 수 있다(새 구간이 맨 오른쪽, 새 구간이 전부를 덮음, 빈 배열). `for`문과 달리 `while`은 범위 확인이 자동으로 없다.
- **`&&` 순서**: `intervals[pos][1] < ... && pos < n` ❌ → `pos < n && intervals[pos][1] < ...` ✅. `&&`는 왼쪽부터 확인하고, 왼쪽이 거짓이면 오른쪽을 실행하지 않는다.

## 재풀이할 때 확인

- [ ] 안 보고 세 `while` 구조로 다시 짜기
- [ ] `[[1,3],[6,9]]`, `[2,5]` → `[[1,5],[6,9]]`
- [ ] `[[1,2],[3,5],[6,7],[8,10],[12,16]]`, `[4,8]` → `[[1,2],[3,10],[12,16]]`
- [ ] `[]`, `[5,7]` → `[[5,7]]` / `[[1,2],[3,5]]`, `[6,8]` (맨 오른쪽) / `[[1,2],[3,5]]`, `[0,10]` (전부 덮음)
- [ ] 범위 확인을 `&&` 맨 앞에 두는 이유를 말로 설명할 수 있다
- [ ] (선택) 넣고 정렬하고 합치는 O(n log n) 풀이도 짜서 비교하기
