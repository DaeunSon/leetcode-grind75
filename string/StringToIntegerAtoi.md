# 8. String to Integer (atoi)

- 링크: https://leetcode.com/problems/string-to-integer-atoi/
- 유형: 구현 (문제의 규칙을 순서대로, 넘침 주의)
- 날짜: 2026-10-29
- 상태: 단계 구조까지 직접 고치고, 넘침 처리는 정답을 보고 완성, 통과. **꼭 재풀이** (안 보고 다시 짜기)

## 접근

문제의 1~4번이 **실행 순서**다. 인덱스 `i` 하나를 단계마다 이어서 쓴다(Insert Interval의 세 `while`과 같은 구조).

1. 앞 공백: `arr[0]`부터 이어진 공백을 전부 건너뛴다.
2. 부호: 그 자리 **한 글자만** 본다. `-`면 음수로 기억하고, `-`나 `+`면 `i++`.
3. 숫자: 숫자가 아닌 글자를 만나거나 끝까지 갈 때까지 `answer * 10 + (c - '0')`.
4. 넘침: `answer`를 `long`으로 두고, 숫자를 더할 때마다 `Integer.MAX_VALUE`를 넘었는지 확인한다. 넘으면 부호에 맞는 끝값을 바로 반환한다.

## 시간복잡도 / 공간복잡도

- 시간: O(n)
- 공간: O(n)  (`toCharArray`. `s.charAt(i)`를 쓰면 O(1))

## 막혔던 점

- Deque가 필요한지 고민했다 → 넣었다가 나중에 꺼낼 게 없으니 필요 없다. **"규칙대로 앞에서부터 읽어라"는 구현 문제**다.
- 처음에는 `for`문 하나에서 모든 글자를 같은 규칙으로 봐서, 숫자 중간의 공백·부호도 받아들였다(`"4 2"` → 42, `"4-2"` → -42).
- **`leading`은 "맨 앞의"라는 뜻**이다. "leading whitespace"는 `arr[0]`부터 이어진 공백만, "leading zeros"는 숫자 맨 앞의 0만 가리킨다. `trailing`은 "맨 뒤의".
- "leading zeros"를 보고 `'0'`을 따로 처리했다가 중간의 0을 빠뜨렸다(`"1023"` → 123). `answer * 10 + 0`이면 앞의 0은 저절로 사라진다. **특수 처리 전에 일반 로직으로 되는지 먼저 확인.**
- `+` 부호를 처리하지 않았다(`"+12"` → 0).
- 부호를 `if` 두 개로 확인해서 `"-+12"`에서 둘 다 받아들였다(-12, 정답 0). **둘 중 하나만이면 `if` / `else if`나 한 `if`로 묶기.**
- 넘침: `int`는 2147483647을 넘으면 음수로 돌아간다. 다 읽은 뒤가 아니라 **읽는 중에** 확인해야 한다(아주 긴 입력은 `long`도 넘는다).
- 문제의 `-231`, `231 - 1`은 복사하며 위첨자가 사라진 것으로 `-2³¹`, `2³¹ - 1`이다(`Integer.MIN_VALUE`, `Integer.MAX_VALUE`).
- `long` → `int`는 자동으로 안 바뀐다 → `(int)` 형변환.

## 재풀이할 때 확인

- [ ] 안 보고 네 단계로 다시 짜기
- [ ] `"   -042"` → -42, `"1337c0d3"` → 1337, `"words and 987"` → 0
- [ ] `"+12"` → 12, `"-+12"` → 0, `"4 2"` → 4, `"1023"` → 1023
- [ ] `"2147483648"` → 2147483647, `"-2147483649"` → -2147483648, `"99999999999999999999999"` → 2147483647
- [ ] 넘침을 왜 읽는 중에 확인해야 하는지 말로 설명할 수 있다
