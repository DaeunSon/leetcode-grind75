# 150. Evaluate Reverse Polish Notation

- 링크: https://leetcode.com/problems/evaluate-reverse-polish-notation/
- 유형: 스택 (연산자가 나오면 가장 최근 숫자 두 개로 계산)
- 날짜: 2026-10-26
- 상태: 숫자와 연산자를 따로 담다가 막혀서 힌트를 받고, 스택 하나로 다시 작성, 통과

## 접근

토큰을 앞에서부터 읽으면서 그 자리에서 바로 처리한다.
- 숫자면 스택에 `push`
- 연산자면 스택에서 두 개를 `pop`해 계산하고, 결과를 다시 `push`
- 다 읽으면 스택에 남은 하나가 답

## 시간복잡도 / 공간복잡도

- 시간: O(n)
- 공간: O(n)  (스택)

## 막혔던 점

- 처음에는 숫자는 스택, 연산자는 큐에 **따로** 담았다. 그러면 연산자가 어느 숫자들 사이에 나왔는지를 잃는다.
  - `["1","2","+","3","*"]` = 9, `["1","2","3","+","*"]` = 5인데, 따로 담으면 둘 다 숫자 `[1,2,3]`, 연산자 `[+,*]`로 같아진다.
  - K Closest에서 거리만 따로 정렬했을 때와 같은 실수다. **값을 떼어놓으면 관계(순서·짝)를 잃는다.**
- 큐에 `push`, 스택에 `add`를 써서 메서드가 의도와 반대였다. 스택은 `push/pop/peek`, 큐는 `offer/poll/peek`만 쓴다.
- `int number;`를 `while` 안에서만 대입하고 `return`해서 컴파일 에러("might not have been initialized")가 났다. 반복문이 0번 돌 수도 있기 때문이다.
- **꺼내는 순서**: 먼저 꺼낸 `a`가 오른쪽 피연산자다. `["4","2","-"]` → `a = 2`, `b = 4` → `b - a = 2`. 그래서 `-`, `/`는 `b - a`, `b / a`.
- 자바의 `/`는 0 쪽으로 버린다(`-7 / 2 = -3`). 문제 조건과 같아서 그대로 쓰면 된다.

## 재풀이 기록 (2026-11-08)

- 결과: 스택 하나 + 꺼내는 순서까지 로직은 혼자 짬. 문자열 비교 실수를 지적받고 고쳐서 통과 (△)
- 지난번 막혔던 곳(숫자·연산자 따로 담기, 꺼내는 순서)은 이번엔 맞게 씀. `a` = 먼저 꺼낸 값(오른쪽), `b - a`, `b / a`
- 틀린 곳
  - `tokens[i].equals('+')`: `'+'`는 `char` → `Character`로 바뀌어 `String`과 비교 → **항상 false**. 컴파일 에러가 안 나서 찾기 어렵다 (`Set.remove(int)`와 같은 함정)
    - 연산자가 `else`로 빠져 `Integer.valueOf("+")` → `NumberFormatException`
    - `calculate` 안만 안 고쳤을 때는 모든 연산이 나눗셈 → `3 / -11 = 0`이 만들어진 뒤 `6 / 0` → `ArithmeticException: / by zero`
  - 고치다가 괄호 `)`를 하나 더 넣어 컴파일 에러
- 다음에 떠올릴 한 문장: "**`String`과 비교할 땐 큰따옴표.** 문제가 0으로 안 나눈다는데 `/ by zero`가 나면 다른 연산이 나눗셈으로 새고 있는 것."
