# 155. Min Stack

- 링크: https://leetcode.com/problems/min-stack/
- 유형: 스택 (최솟값을 따로 쌓는 보조 스택)
- 날짜: 2026-10-21
- 상태: 틀(`push`/`pop`/`top`)까지 직접 짜고 `getMin`에서 막혀 정답을 보고 작성, 통과. **꼭 재풀이** (안 보고 다시 짜기)

## 접근

스택을 두 개 둔다. `deque`에는 값을, `min`에는 "이 칸까지 쌓였을 때의 최솟값"을 넣는다.
`push`할 때 `min`이 비어 있으면 값 그대로, 아니면 `Math.min(값, min.peek())`를 넣는다.
`pop`할 때는 두 스택을 같이 꺼낸다. 두 스택은 항상 높이가 같아서, 꺼내면 바로 아래 칸의 최솟값이 다시 맨 위로 올라온다.

## 시간복잡도 / 공간복잡도

- 시간: 모든 연산 O(1)
- 공간: O(n)  (스택 두 개)

## 막혔던 점

- 최솟값을 변수 하나에 저장하면 `pop`할 때 이전 최솟값을 알 수 없다.
  - 예: `push(3)`, `push(1)`, `pop()` → 정답은 3인데, 변수에는 1이 남아 있고 3은 이미 덮어써서 사라졌다.
  - `getMin`할 때마다 스택을 다 훑으면 O(n)이라 조건(O(1))에 안 맞는다.
- **되돌릴 수 있는 상태(최솟값 등)는 원소와 함께 스택에 쌓아둔다.** 그러면 `pop`이 상태도 같이 되돌려준다.
- 처음 틀에서 고친 것
  - `ArrayDeque`에는 `top()`이 없다. 꺼내지 않고 보기만 하는 메서드는 `peek()`이다.
  - 반환형이 `int`인 메서드(`top`, `getMin`)에 `return`이 없으면 컴파일 에러가 난다.

## 재풀이할 때 확인

- [ ] 안 보고 두 스택 방식으로 다시 짜기
- [ ] 스택 하나에 `int[]{값, 그때의 최솟값}`을 넣는 방식으로도 짜보기
- [ ] `push(-2)`, `push(0)`, `push(-3)` → `getMin()` = -3, `pop()` → `top()` = 0, `getMin()` = -2
- [ ] `push`에서 `min`이 비어 있을 때를 왜 따로 처리하는지 말로 설명할 수 있다
